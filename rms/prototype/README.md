# RMS Prototype: ต้นแบบระบบบริหารจัดการเงินทุนวิจัย

ต้นแบบแบบคลิกได้ ครอบคลุม flow หลักของ MVP ตามเอกสาร [03-requirements.md](../docs/03-requirements.md)
เป็นไฟล์ HTML ไฟล์เดียว ไม่มี backend ข้อมูลทั้งหมดเป็นตัวอย่างสมมติ และเก็บใน `localStorage` ของเบราว์เซอร์

## วิธีรัน

```bash
cd rms/prototype
python3 -m http.server 8000
# เปิด http://localhost:8000
```

หรือดับเบิลคลิกเปิด `index.html` ในเบราว์เซอร์โดยตรงก็ได้

> ไฟล์นี้เขียนตามรูปแบบหน้า Artifact ของ claude.ai (ไม่มี `<!doctype html>`)
> ถ้าเปิดในเบราว์เซอร์โดยตรง จะแสดงผลได้ แต่อยู่ใน quirks mode

## วิธีใช้

- **สลับบทบาท:** ใช้เมนู "ดูในบทบาท" มุมขวาบน
  ถ้ากำลังเปิดดูเรื่องใดอยู่ หน้าจอจะค้างที่เรื่องนั้น จึงทำขั้นถัดไปในบทบาทใหม่ต่อได้ทันที
- **รีเซ็ตข้อมูลตัวอย่าง:** กดปุ่มรีเซ็ต 2 ครั้ง ข้อมูลจะกลับไปเป็นชุดเริ่มต้น

## สถานการณ์ตัวอย่างสำหรับสาธิต

| # | สถานการณ์ | ขั้นตอน |
|---|---|---|
| 1 | **ทำสัญญาแบบไม่ใช้กระดาษ** (RMS-2569-014) | นักวิจัยลงนาม → คณะอนุมัติ → ผู้มีอำนาจลงนาม → ระบบสร้างกำหนดส่งรายงานและคำขอเบิกงวด 1 ให้เอง |
| 2 | **รายงานผ่านแล้วระบบสร้างคำขอเบิกงวดถัดไปให้** (RMS-2569-001) | นักวิจัยส่งรายงานความก้าวหน้า → คณะรับรอง (ทุนภายในไม่ต้องมีผู้ทรงฯ) → คำขอเบิกงวด 2 ถูกสร้างอัตโนมัติ |
| 3 | **Rule engine จับภาระค้าง** | ต่อจากข้อ 2: นักวิจัยยืนยัน → คณะอนุมัติ → ระบบพบเงินยืมเลยกำหนดล้างหนี้ จึงส่งไปคิวข้อยกเว้นของกองวิจัย → อนุมัติข้ามกฎพร้อมเหตุผล หรือส่งกลับ |
| 4 | **ตรวจงบก่อนขอใช้จ่าย** | นักวิจัย → โครงการ → แท็บ "งบประมาณและการใช้จ่าย" → ลองใส่ยอดเกินงบคงเหลือ ระบบจะไม่ให้ส่ง |
| 5 | **ยืมเงินและล้างหนี้** | นักวิจัยเปิดเงินยืมที่เลยกำหนด → แนบหลักฐาน → การเงินตรวจผ่าน → ยอดผูกพันกลายเป็นยอดใช้จริง |
| 6 | **ทุนภายนอกต้องผ่านผู้ทรงคุณวุฒิ** (RMS-2568-087) | คณะรับรองรายงาน → บทบาทผู้ทรงคุณวุฒิประเมิน → ผ่าน → ระบบสร้างคำขอเบิกงวด 2 |
| 7 | **ปิดโครงการพร้อมคืนเงินเหลือจ่าย** (RMS-2568-052) | กองวิจัยเปิด checklist → แจ้งคืนเงิน 12,500 บาท → นักวิจัยแจ้งชำระ → การเงินยืนยัน → กองวิจัยปิดโครงการ → ระบบตั้งการติดตามผลผลิตหลังปิด |
| 8 | **อนุมัติแบบกลุ่ม** | บทบาทคณะหรือผู้มีอำนาจ → ติ๊กหลายเรื่องในกล่องงาน → "อนุมัติเรื่องที่เลือก" |
| 9 | **นำเข้าโครงการใหม่** | บทบาทกองวิจัย → "นำเข้าโครงการ" → สัญญาถูกสร้างจาก template ทันที |
| 10 | **ภาพรวมผู้บริหาร** | บทบาทผู้บริหาร → แดชบอร์ด: KPI, รายคณะ, คอขวดตามผู้ถือเรื่อง, ความเสี่ยง |

## สิ่งที่ต้นแบบนี้จำลอง และสิ่งที่ยังไม่ได้ทำ

| อยู่ในต้นแบบ | ยังไม่มี (ระบบจริงต้องมี) |
|---|---|
| Workflow engine กลาง + SLA + audit trail | การส่งเรื่องขึ้นไปเมื่อเกิน SLA, ผู้ปฏิบัติแทน |
| Rule engine ตรวจเงื่อนไขงวด | หน้าจอให้ ADMIN แก้กฎ |
| Funder profile (แสดงอย่างเดียว) | หน้าจอเพิ่มหรือแก้แหล่งทุน, form builder |
| สร้างสัญญาจาก template (แสดงเป็นข้อความ) | DOCX→PDF จริง, e-Signature จริง, ขั้นนิติการ |
| Budget ledger (ผูกพัน / ใช้จริง) | เชื่อม SAP (เฟส 1.5 / 2) |
| — | Change request (ขยายเวลา / ปรับงบ), SSO, การแจ้งเตือนทางอีเมล |

## โครงสร้างโค้ด (`index.html`)

- `WF`: นิยาม state machine ของแต่ละเรื่อง ได้แก่ สถานะ, บทบาทผู้ถือเรื่อง, SLA, action และฟอร์ม
- `HOOKS`: ผลต่อเนื่องเมื่อเข้าสถานะใหม่ เช่น สัญญามีผล → สร้างคำขอเบิกงวด 1
- `runRules()`, `ledger()`, `closeChecks()`, `refundDue()`: business logic หลัก
- `FUNDERS`: กติกาของแหล่งทุน (ตัวอย่าง)
- `seed()`: ข้อมูลตัวอย่าง (บุคคลและโครงการสมมติทั้งหมด)
