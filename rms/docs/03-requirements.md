# 03 — เอกสาร Requirement: ระบบบริหารจัดการเงินทุนวิจัย (RMS)

> **Input:** [02-to-be-process.md](02-to-be-process.md)
> **ลำดับความสำคัญ (MoSCoW):**
> - **M** = Must: ต้องมีใน MVP
> - **S** = Should: ควรมีใน MVP ถ้าทำทัน หรือมีในรุ่นถัดไป
> - **C** = Could: ทำเมื่อมีเวลา
> - **W** = Won't (this phase): ไม่ทำในเฟสนี้

## 1. บทบาทผู้ใช้ (Roles)

| Role | คำอธิบาย | ขอบเขตข้อมูลที่เห็น |
|---|---|---|
| `PI` | หัวหน้าโครงการ | โครงการของตนเอง |
| `CO_PI` | ผู้ร่วมวิจัย | โครงการที่ตนร่วม (อ่าน และส่งรายงาน/ใช้จ่ายได้ถ้า PI มอบสิทธิ์) |
| `FAC_OFFICER` | ผู้ประสานงานวิจัยระดับคณะ | โครงการในคณะของตน |
| `FAC_HEAD` | หัวหน้าส่วนงาน / คณบดี / ผู้ได้รับมอบหมาย | โครงการในคณะของตน (อนุมัติ) |
| `RO_OFFICER` | เจ้าหน้าที่กองบริหารงานวิจัย | ทุกโครงการ |
| `LEGAL` | นิติการ | สัญญาที่ถูกส่งมาให้ตรวจ |
| `FIN_OFFICER` | เจ้าหน้าที่การเงิน / พัสดุ | ข้อมูลการเงินของทุกโครงการ |
| `APPROVER` | ผู้มีอำนาจอนุมัติตามวงเงิน | เรื่องที่รออนุมัติ และรายงานภาพรวม |
| `REVIEWER` | ผู้ทรงคุณวุฒิ (อาจเป็นบุคคลภายนอก) | เฉพาะรายงานที่ได้รับมอบหมาย |
| `EXEC` | ผู้บริหาร | dashboard ภาพรวม (อ่านอย่างเดียว) |
| `ADMIN` | ผู้ดูแลระบบ | ตั้งค่าระบบ |

## 2. User Stories แยกตามบทบาท

### นักวิจัย (PI)

| ID | User Story | Acceptance Criteria หลัก | P |
|---|---|---|---|
| US-PI-01 | ในฐานะ PI ฉันต้องการเห็นโครงการทั้งหมดของฉัน พร้อมสถานะและสิ่งที่ต้องทำ เพื่อจะได้ไม่ต้องโทรถาม | หน้าแรกแสดงรายการ "รอฉันดำเนินการ" เรียงตามกำหนด และทุกเรื่องแสดงสถานะ ผู้ถือเรื่อง และจำนวนวันที่รอ | M |
| US-PI-02 | ต้องการตรวจข้อมูลสัญญาที่ระบบสร้างและลงนามออนไลน์ | ดู PDF ได้ก่อนลงนาม ขอแก้ไขพร้อมเหตุผลได้ และหลังลงนามเรื่องไปที่คณะอัตโนมัติ | M |
| US-PI-03 | ต้องการยืนยันคำขอเบิกงวดที่ระบบสร้างให้ โดยไม่ต้องกรอกใหม่ | คำขอมีเลขงวด ยอด และเงื่อนไขที่ผ่านแล้วเติมไว้ครบ ยืนยันได้ใน 1 คลิก | M |
| US-PI-04 | ต้องการเห็นงบคงเหลือตามหมวดแบบ real-time | แสดงงบ ยอดผูกพัน ยอดใช้จริง และยอดคงเหลือ ต่อหมวด ข้อมูลไม่เก่ากว่า 1 วัน (หรือ real-time ถ้า SAP รองรับ) | M |
| US-PI-05 | ต้องการขอจัดซื้อจัดจ้างหรือยืมเงินผ่านระบบ | ระบบตรวจงบหมวดนั้นก่อนส่ง ถ้างบไม่พอส่งไม่ได้ และเมื่ออนุมัติแล้วตั้งยอดผูกพันทันที | M |
| US-PI-06 | ต้องการส่งหลักฐานล้างเงินยืม และรู้ว่าเหลือกี่วัน | นับถอยหลังกำหนดล้างหนี้ เตือนก่อนครบ 7 และ 1 วัน และรองรับไฟล์ PDF/JPG หลายไฟล์ | M |
| US-PI-07 | ต้องการส่งรายงานความก้าวหน้าผ่านแบบฟอร์มของทุน | ช่องที่จำเป็นต้องครบจึงจะส่งได้ รายงานการเงินสร้างจากระบบ และบันทึกผลผลิตได้ในรายงานเดียวกัน | M |
| US-PI-08 | ต้องการเห็นความเห็นของผู้ทรงคุณวุฒิและส่งฉบับแก้ไข | comment ผูกกับ version และเห็นประวัติทุก version | M |
| US-PI-09 | ต้องการขอขยายเวลาหรือปรับแผนงบ | ใช้ฟอร์ม change request เดียว และระบบบอกเส้นทางอนุมัติก่อนกดส่ง | M |
| US-PI-10 | ต้องการรู้ยอดเงินที่ต้องคืนตอนปิดโครงการและชำระได้สะดวก | ระบบคำนวณยอดตามกติกาทุนและออกใบแจ้งชำระหรือ QR | S |
| US-PI-11 | ต้องการมอบสิทธิ์ให้ผู้ร่วมวิจัยหรือผู้ช่วยวิจัยทำงานแทนบางส่วน | มอบสิทธิ์รายเรื่องได้ (ส่งรายงาน / ขอใช้จ่าย) และบันทึกใน audit log | S |
| US-PI-12 | ต้องการดึงผลงานตีพิมพ์จาก ORCID มาใส่เป็นผลผลิต | เชื่อม ORCID แล้วเลือกผลงานมาผูกกับโครงการได้ | C |

|---|---|---|---|

| US-FAC-03 | ในฐานะผู้ประสานงานคณะ ต้องการเห็นโครงการในคณะที่ใกล้ถึงหรือเลยกำหนด | ตัวกรองตามสถานะและกำหนดส่ง และ export Excel ได้ | M |

### กองบริหารงานวิจัย (RO_OFFICER)

| ID | User Story | Acceptance Criteria หลัก | P |
|---|---|---|---|
| US-RO-01 | ในฐานะเจ้าหน้าที่กองวิจัย ฉันต้องการนำเข้าโครงการที่อนุมัติแล้วจากไฟล์หรือระบบต้นทาง | import จาก Excel template ได้ ระบบ validate ก่อนนำเข้า และแสดงรายการที่ผิดพร้อมเหตุผล | M |

| US-RO-03 | ต้องการเห็นเฉพาะคำขอที่ไม่ผ่านกฎอัตโนมัติ | คิวข้อยกเว้นแสดงกฎที่ไม่ผ่าน และอนุมัติข้ามกฎได้พร้อมเหตุผล (บันทึก log) | M |
| US-RO-04 | ต้องการมอบหมายผู้ทรงคุณวุฒิและติดตามผลประเมิน | เลือกผู้ทรงฯ (ภายในหรือภายนอก) กำหนดวันส่ง ระบบเตือนอัตโนมัติ และเห็นสถานะการประเมิน | M |
| US-RO-05 | ต้องการตั้งค่าแหล่งทุนใหม่ (funder profile) โดยไม่ต้องให้โปรแกรมเมอร์แก้ | กำหนดหมวดงบ กติกางวด รูปแบบรายงาน กติกาคืนเงิน และรูปแบบ export ผ่านหน้าจอ | M |
| US-RO-06 | ต้องการ export รายงานในรูปแบบที่แหล่งทุนภายนอกต้องการ | export ตาม funder profile (PDF/Excel/CSV) | S |
| US-RO-07 | ต้องการเห็นนักวิจัยที่ค้างภาระ | รายชื่อพร้อมเหตุ (ค้างรายงาน / ค้างเงินยืม / ค้างคืนเงิน / ค้างผลผลิต) | M |

## 4. Non-functional Requirements

| ID | หมวด | Requirement | P |
|---|---|---|---|
| NFR-01 | Authentication | SSO กับบัญชีมหาวิทยาลัย (SAML / OIDC / Azure AD) และ OTP ทางอีเมลสำหรับผู้ทรงฯ ภายนอก | M |
| NFR-02 | Authorization | RBAC + ขอบเขตข้อมูลตามหน่วยงานและโครงการ (row-level) | M |
| NFR-03 | Audit trail | บันทึกทุกการเปลี่ยนแปลงข้อมูลและทุกการอนุมัติ (ใคร / อะไร / เมื่อไร / ค่าก่อน-หลัง) ห้ามแก้ไขหรือลบ และเก็บไม่น้อยกว่า 10 ปี 🟡 | M |
| NFR-04 | PDPA | เก็บข้อมูลส่วนบุคคลเท่าที่จำเป็น, กำหนดวัตถุประสงค์, จำกัดผู้เข้าถึง, ปิดบังเลขบัตร/เลขบัญชีบางส่วน, มีนโยบายระยะเวลาเก็บ | M |
| NFR-05 | Security | HTTPS, เข้ารหัสข้อมูลอ่อนไหวขณะจัดเก็บ, ป้องกันตาม OWASP Top 10, สแกนไวรัสไฟล์ที่อัปโหลด, pentest ก่อน go-live | M |
| NFR-06 | Availability | 99.5% ในเวลาทำการ, สำรองข้อมูลรายวัน, RPO ≤ 24 ชม., RTO ≤ 8 ชม. | M |
| NFR-07 | Performance | หน้าทั่วไปโหลดเสร็จใน 3 วินาที, รองรับผู้ใช้พร้อมกัน 300 คน 🟡 (ต้องยืนยันปริมาณงานจริง) | M |
| NFR-08 | Usability | Responsive (ใช้บนมือถือได้สำหรับการอนุมัติ), ภาษาไทยเป็นหลัก, รองรับภาษาอังกฤษ | M |
| NFR-09 | Integration | เชื่อม SAP ผ่าน integration layer ที่เปลี่ยน adapter ได้ (ECC → S/4HANA) โดยไม่แก้ core | M |
| NFR-10 | Data residency | เก็บข้อมูลบน data center ของมหาวิทยาลัยหรือ cloud region ที่อนุญาต | M |
| NFR-11 | Maintainability | ทีม IT ขนาดเล็กดูแลได้, tech stack เป็นที่นิยม, มีเอกสาร, test อัตโนมัติ | M |
| NFR-12 | e-Signature | เป็นไปตาม พ.ร.บ.ธุรกรรมทางอิเล็กทรอนิกส์ (ลายมือชื่ออิเล็กทรอนิกส์ที่เชื่อถือได้) และตรวจสอบความถูกต้องของเอกสารได้ | M (📜R1) |
